# 更新记录

下列记录对应各次开发时的能力与验证结果，不代表当前版本已覆盖所有环境。

## 1.0.36 评论弹窗展示原文

添加评论弹窗在输入框上方显示选中原文，带“原文”标签。编辑评论和手机／平板回复弹窗也显示所属讨论的原文，方便写作时对照。引用按纯文本展示，保留换行、可复制；较长引用在区域内滚动，不裁掉文本。手机横屏时压缩引用区高度，保留输入与发送空间。引用来自打开弹窗时的选区或讨论，不随光标变化，也不会混入评论内容或草稿。

## 1.0.35 评论导航按需显示

增加“显示评论导航按钮”设置，默认关闭，开启后显示上一条／下一条讨论按钮，保存后立即更新已打开的评论侧栏。未设置过此选项的用户升级后也默认隐藏。

隐藏导航时移除操作区边框、分隔线和多余间距，将解决／重新打开讨论按钮向右收紧，给原文摘录留出更多横向空间。手机和平板保持 44 像素触控目标，原文与操作区同行显示；只读模式没有操作时不保留空占位。全部文档的返回合并展示按钮继续保留。

## 1.0.34 手机横屏输入优化

补测手机横屏后，修复低可视高度下抽屉内回复按钮被底部栏遮挡的问题。手机和平板点击“回复”打开独立弹窗，发送按钮随键盘可视高度调整，旋转屏幕后保留输入草稿。

在高度不超过 500 像素的移动布局中，搜索和筛选默认收起，可从顶部筛选按钮展开；保留评论与标记切换，增加列表可用空间。移动端菜单打开期间，数据和编辑权限没有变化的布局刷新不再关闭菜单。

## 1.0.33 手机与平板评论标记

手机和平板支持阅读模式下新增评论、回复、编辑、删除、解决讨论及添加和删除标记。长按选中文字后，底部显示“标记”“评论”；已有下划线和高亮可点开对应批注。支持大屏手机、iPad 横竖屏和窄分屏，主要操作使用 44 像素触控目标。

手机回复框按回车换行，点击“发送”提交。评论弹窗按键盘可视高度调整，提供加粗和有序／无序列表。标记后留在正文，批注抽屉增加“返回阅读”。编辑模式下仍只读批注。

移动端保存使用与桌面相同的原子创建、比较写入和冲突保护，读缓存按文件变化失效。选区监听按文档统一注册并防抖；沿用讨论分页与消息分批显示。手机缺少尚未同步的笔记时不自动写入删除状态，迁移仍在桌面端执行。

## 1.0.32 迁移目标目录预填

迁移目标目录直接预填 `Highnote/annotations`，避免将灰色占位提示误认为已经填写的目录。用户可以保留默认值或修改为其他相对目录。清空源目录或目标目录时，明确提示缺少哪个目录，聚焦对应输入框，不启动迁移。

## 1.0.31 历史批注迁移

新安装默认将批注保存到 `Highnote/annotations`，升级保留已明确设置的目录。桌面设置增加“迁移批注数据”：源目录默认 `.obsidian-highnote`，用户填写目标相对目录后点击“迁移”，成功后自动切换。识别源目录及 `annotations` 子目录的批注文件，保留原始内容与源文件备份。

迁移逐文件校验和复制，显示进度；同名相同内容跳过，同名不同内容或损坏数据则停止，避免覆盖。中途失败不切换当前目录，重试可复用已复制文件。迁移期间暂停批注修改，保存设置成功后才切换。手机仍只读批注，并可配置同步后的目录。

## 1.0.30 可配置批注数据目录

电脑和手机的“设置 → Highnote”增加“批注数据目录”、应用与恢复默认按钮。填写完整的笔记库内相对路径，例如 `Highnote/annotations`，默认仍为 `.obsidian-highnote/annotations`。使用 Obsidian Sync 时选择普通目录，并在两端开启“同步所有其他类型”。导出文件继续保存到笔记库根目录。

切换立即读取目标目录，不自动复制、合并或删除原目录数据。目录不存在时在桌面端首次保存批注时创建，手机只读。校验路径、父目录类型及目标数据，切换失败保留原配置和缓存；有评论草稿、打开的批注窗口或正在导出时先完成当前操作。切换前处理已排队操作，关闭旧监听并清理位置与回顾缓存；旧窗口不能写入已切换的数据源。

188 个自动化用例、TypeScript 构建及官方规范 lint 通过。在 Obsidian 1.14.4 验证桌面设置应用、目录独立读写、重载记忆、非法与损坏目标拒绝、外部更新监听、草稿保护，以及移动模拟模式中的设置和只读回顾。未进行 iOS／Android 真机验证。

## 1.0.29 手机版阅读回顾

手机版可以从书本图标或命令打开阅读回顾，查看原文摘录、评论与回复全文、已有标记，搜索、按日期筛选、查看出处并打开原笔记。热力图默认收起，记住展开状态；按钮与日期触控区域加大，适配窄屏和深色主题。保留 Markdown、HTML 与 flomo CSV 导出，手机端只保存 HTML／CSV 文件。

手机端不注册评论侧栏、编辑器扩展和正文标注，也不显示选区浮层。批注数据只读，笔记缺失、改名、修改或删除不会写回批注 JSON。桌面端继续支持原有评论、标记、文件监听与导出行为。Node.js／Electron 仅在桌面分支加载，构建将延迟导入转换为 Obsidian 提供的 CommonJS 加载方式。

回顾打开、应用回前台或手动刷新时重新读取数据；回顾处于前台时每 15 秒检查文件信息，只读取变化的文件。复用未变化的解析结果与索引，空 JSON 不触发重复重绘。卡片和长讨论继续分批渲染。

沿用 `.obsidian-highnote/annotations/`。Obsidian Sync 不同步该隐藏目录，需要其他支持隐藏目录的同步方式或手动复制，已在中英文 README 和手机空状态中说明。

结合实际 DOM 选区，在整块文字可对应时区分同段重复文字和标题／正文中的相同文字。选区使用当前渲染块的原文快照，避免打开文档后立即操作时受异步缓存读取影响；不能可靠对应的内容仍拒绝绑定。按文本节点收集选区位置，定位只处理所在文本块，不遍历评论数据。

## 1.0.19 原文优先回顾与 flomo 导出

通过“Highnote：打开阅读回顾”命令，或侧栏“…”里的“阅读回顾”，在主工作区查看已保存内容。同一讨论一张卡片，原文放在上方浅灰引用中，下面连续展示评论和回复全文。来源、状态及创建／修改时间放到“查看出处与讨论”中，首页省去重复信息。卡片按讨论中最新纳入消息的创建时间倒序，编辑不改变创建顺序。评论／标记页签、搜索及回复显示保留，没有新增标签功能。

日期热力图默认收起，展开显示可翻页的三个月。色深统计当前搜索中各条消息的创建日期，点击某天筛选相关讨论，并保留讨论上下文、标示当天消息；关键词保留。窄窗口下热力图可以横向滚动。宽窗口可分栏查看原文，窄窗口打开新标签；重复点击复用来源区域，已固定或切到编辑模式的区域受到保护。回顾只查看，修改仍回原文阅读模式操作。

新增记录保存创建时摘录 `originalQuote`；评论正文实时显示最新版本。原文后续变化时，定位使用可跟随原文的锚点，回顾保留原始摘录。旧记录没有原始摘录时展示现有摘录并注明，不猜测历史内容。

回顾右上角“导出”提供 **Markdown、HTML、flomo CSV**。Markdown／HTML 都采用原文在上、评论连续的阅读布局，元数据折叠。导出当前选择的文档范围，**首页搜索、日期和回复显示不缩小导出**；CSV 有独立的回复选项。默认存笔记库根目录，重名追加序号，导出文件是独立快照。原侧栏 Markdown／HTML 导出继续可用。

flomo CSV 默认一段讨论生成一条笔记，包含回复，正文先“原文”后“想法”。可改为每条消息独立导出，选择只保留评论、隐藏标题、附上文档名，以及空行／换行／分隔线／自定义连接文字。进阶模板支持 `{上下文}`、`{评论}`、`{来源}`、`{记录日期}`；模板单次替换，非法变量会提示，取消不保存配置，导出成功后按笔记库记住配置。

CSV 使用 UTF-8 BOM、固定 `content,created_at` 两列、CRLF 行尾与标准双引号转义。正文为纯文本，原有加粗等标记原样保留，创建时间按电脑本地时区格式化。合并模式优先使用主评论创建时间，缺失时取最早有效回复时间；全部缺失留空并提示。插件只生成本地 CSV，不登录或上传 flomo；跨次导入不保证自动去重，真实 flomo 账号导入尚未验证。

回顾每批最多 40 张卡片，长讨论和 Markdown／HTML 预览每批最多 40 条消息，全文可以翻批查看，导出数量不受分页限制。搜索有 180ms 延迟、增量索引和有界缓存；分组随数据、范围和回复选项更新，输入搜索词不重新分组。CSV 只显示一条实际正文预览，相同数据和配置复用结果。

120 个自动化用例、构建和官方规范检查通过，另在 Linux Obsidian 1.14.4 验证三种格式、预览与标准 CSV 解析一致、配置持久化、取消、失败重试、防重复提交、完整讨论、来源定位与浅深／窄屏布局。2 万条合成记录的实机检查：回顾首屏约 50ms，CSV 预览约 168ms，完整 CSV 保存约 375ms，复用预览约 1ms；只渲染 40 张卡片和 1 条导出预览。耗时随设备和正文长度变化，尚未验证十万条、真实多文件同步与磁盘加载，单文件 JSON 写入成本仍随该文件评论量增长。

## 1.0.12 导出更新

导出入口合并为“导出评论”或“导出标记”。一个弹窗选择当前／全部文档、Markdown／HTML、文件名，并显示范围计数和小幅预览。默认沿用侧栏范围；首次使用 Markdown，此后记住上次成功保存的格式，取消和失败不更新。文件扩展名跟随格式，默认存笔记库根目录，重名自动追加序号。

Markdown 在 Obsidian 阅读模式打开，按文档分组并提供目录，回复通过引用缩进区分。HTML 用系统默认浏览器打开，单文件离线可读，包含文档目录、搜索高亮、处理状态／定位筛选、回复展开与收起、明暗主题、舒展／紧凑布局和打印。两种格式都保留所选范围内全部已保存内容，不受侧栏搜索、状态或分页影响；未提交草稿不导出。

HTML 自动关联导出时的笔记库名称。“打开原文件”只打开文件，不尝试定位旧句子。打印当前筛选出的内容，展开回复，明确显示数量；深色页面打印为浅色。导出后原笔记修改、改名或移动不会更新已有快照。系统浏览器打开失败时文件仍保留，并提示保存位置。

卡片右上角放上一条／下一条和解决按钮，各条消息保留独立“…”菜单，仅提供编辑、删除。移除“删除整个讨论”入口；逐条删除保留其他回复，当最后一条未删除消息也删除时移除空讨论及下划线，同段标记保留。保存时重新检查是否仍有回复，避免并发删除造成丢失。

## 1.0.11 阅读侧栏

侧栏采用克制的阅读布局：淡蓝选中背景、蓝色左边线，原文引用放在顶部，评论正文和回复在下方。保留 14px 评论正文、13px 引用和 12px 时间／状态；明暗主题跟随 Obsidian，不调整笔记正文字号。

评论和回复默认完整展示。原文引用最多两行，通过独立“展开原文”查看全文，点击摘录用于定位；点击评论内容仅选中，保持当前正文位置。标记仍支持整张卡片定位。失效记录只选中并提示，不切换源文件；不提供重新绑定或额外的专注阅读入口。

默认显示未解决评论，处理状态可选全部／未解决／已解决，独立“仅看无法定位”包含位置失效和原文件已删除，可与搜索组合。标记仅显示定位筛选。标签总数不随筛选变化，筛选结果显示“匹配数 / 总数”，支持一键清除筛选。

当前文档按原文顺序展示，无法定位的记录放末尾。全部文档按相对路径固定分组，组内同样按原文排序；文件标题默认隐藏路径并显示数量，同名文件补充足够的父目录，点击标题可展开完整相对路径。全部文档继续合并同一讨论的消息，内容不截断，点击可展开完整消息及回复操作。

每次先渲染 40 条，按需加载更多。路径区分使用目录后缀计数，避免同名文件逐个互相比对。存储结构和导出范围沿用既有实现。

## 既有能力

侧栏顶部依次显示标题与范围、页签、搜索、状态与定位筛选。导出和“重新加载数据”移到标题旁的“…”菜单；默认不重复显示范围与数量，只在搜索或特殊状态筛选时显示结果数。标记卡片移除常驻“有效”，点击卡片可打开对应文件并定位，拖选摘录与删除按钮不触发跳转。

标记颜色改为两排预设色块，选中色显示边框和勾选，提供自定义六位颜色值及恢复默认，不提供透明或无颜色。已有标记使用统一颜色。

跨文件定位先按源码行滚动，让长文档目标段落渲染，再定位摘录。重复摘录按已保存的位置区分；已解决讨论也可定位，失效记录只选中并提示，不切换源文件，原文件已删除时保留记录。定位不会为了找文字切到编辑模式。

阅读模式选中文字后，浮层增加荧光笔按钮，点击直接高亮并保存到插件数据。标记与评论独立，同一段文字可同时使用两者；重复标记不新增，重叠范围合并，相邻范围保持独立。侧栏增加“标记”页签，支持当前／全部文档查看、搜索、定位和整条删除，不提供备注、回复、标签或解决状态。

所有标记共用一种颜色，初始为黄色。在“设置 → Highnote → 标记颜色”选择预设，或打开“自定义”拖动选色、输入 HEX／RGB 后点击“应用”，已有标记同步换色，选区浮层不增加颜色菜单。

**仅阅读模式允许新增、回复、编辑、删除、解决及导出。** 编辑模式和实时预览仅查看侧栏内容、搜索、筛选与定位，正文不显示标注或选区浮层。后台仍记录编辑事务，跟随原文位置；切回阅读模式后恢复操作，未发送草稿保留。

评论和标记各自支持当前／全部文档 Markdown 导出，入口随页签变化。包含文件名、库内相对路径、完整摘录、时间和状态；评论另含全部已保存消息。导出不受搜索、状态筛选或分页影响，默认存笔记库根目录，重名追加 `(1)` 等序号，完成后以阅读模式打开。草稿不导出。

修复新建评论可能被旧编辑窗口文本或后台同步误判失效的问题，逐事务区分用户输入与同步，位置校验使用当前原文基线。原文实际删除、完整替换或无法可靠定位时继续保留失效记录，已有失效记录不自动恢复。选区取消后补刷延后的标注；位置保存冲突后可重新读取最新数据，并保留输入草稿。

每篇有评论或标记的笔记仍对应一份 42 字符名称的 JSON，新增标记数组；1.0.6 至 1.0.8 的聚合评论可继续读取。不要降级使用旧插件写入含标记的新数据。更早的 UUID、64 位摘要测试文件保留但不加载，也不自动迁移。

当前文档完整显示评论和回复。全部文档按文件名和库内相对路径分组，将同一讨论的未删除消息按顺序用“ · ”合并展示，保留状态与时间，省去回复框。评论正文不限制行数；点击合并内容可就地打开完整讨论，收起后回复草稿保留。
